## Fresh trajectory, checkpoints and exact reconstruction

The runtime was constructed once before the 1000-step master loop. Its callback
wrote a separately authenticated compact stream during every advance, preserving
the runtime stream head each year. Unsealed frames retain their explicit
`DEFERRED_UNTIL_MATERIALIZATION` canonical-SHA status. Stream hashes were never
substituted for full canonical snapshot hashes.

Every hot step exported exactly 11 newly appended deposit rows. Complete
historical snapshots were not built by the loop, and the regional frontier was
not cold-imported each year. Water/solid balances, clock and journal continuity
were checked annually; original Unified physical/Deep validation remained active.

After the master loop, a reader opened the **new disk journal**, verified its
closed chain and reconstructed all original payloads in sequence. Each kind and
canonical SHA matched the independent original INDEX, including:

- 1001 complete nine-cell snapshots and 11,000 final deposit rows;
- 58,000 events, with all **8000 NULL timestamps** preserved;
- 1000 regional annual records and 1000 Unified/Deep records;
- all material IDs, masses, densities, provenance, nondeposit state values,
  ordering, balances and UNKNOWN/null representations covered by those hashes.

The reconstructed full files were then independently read and hashed:

- HISTORY: **1,916,080,917 B**, SHA
  `a440789579ec5362f175fa1274a837516bdea196fcc1d9095feacf0f4a3ddf34`;
- INDEX: **10,685,396 B**, SHA
  `8178d2130cdbb509e12b292552a77870693b239ffdf3b97748a23acdea7cd529`.

Both whole files are byte-identical to the original. The compact file itself is
a different format; no physical byte equality with legacy HISTORY is claimed.

Native R2 checkpoint export uses the original history-independent checkpoint
schema. All five milestone checkpoint files are therefore **byte-identical**,
not merely physically equivalent, to the original checkpoint files.

## Remaining limits and 10k evaluation — not execution

The engineering gate is complete. B0 atomic publication, production durability,
crash recovery and adaptive per-domain retention remain outside qualification.
Canonical full snapshot hashing, all-year compatibility generation and five
ordered deposit scans retain O(D) or O(sum D) costs. Imports, native checkpoints,
and full queries are explicit; the in-memory journal grows with actual history.

Before a separately authorized integrated 10k benchmark:

1. Bind the reviewed uncommitted source snapshot or a separately authorized
   commit, measured-file SHAs, E0 pins, config and run identity. No automatic
   commit/push is permitted. The present runner is fixed to 1000; a reviewed
   10k runner/contract is required, rather than changing a hidden parameter.
2. Use one continuous runtime with `planned_years=10000`, one-year advances and
   the same 3×3/two-column model only after scope/validity review. Resolve uplift:
   total 0.1 m over 1000 steps is 0.0001 m/year; retaining total 0.1 over 10000
   gives 0.00001 m/year. Preserving the original annual rate would need total
   1.0 m, a distinct parameter decision. Neither was silently selected here.
3. Recheck actual site context/allocation, ancestor cgroups, storage/quota and
   memory at launch. This 1000Y session permission is not a 10k authorization.
   Do not infer reserved cores from visibility or add arbitrary program caps.
4. Explicitly select checkpoint/query/full-materialization services. The current
   resident journal and naive whole-stream queries must be reviewed for the
   longer horizon. A giant legacy export must be a declared, separately timed
   requested service; no unvalidated global runtime/RAM/disk extrapolation is
   used as qualification.
5. Preserve annual and 100Y windows, exclusive phase observations, CPU/core
   utilization, process-tree/RSS, logical/allocated bytes, file/event/deposit
   counts, all integrity, replay and failure evidence. Stop on real invariant
   failure; no automatic retries, source resets or patch stacking.
