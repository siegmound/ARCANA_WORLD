## Classification summary

- `DIRECT_REUSE`: none. No existing R3–R5 module was imported into the R6 public package; existing implementations are stage-bound or carry scientific/runtime dependencies not suitable as a clean R6 core dependency.
- `EXTRACT_GENERIC_PRIMITIVE`: no legacy source file was refactored in this wave. The R6 core owns a deliberately small canonical identity primitive because the inspected reusable serializers are private/stage-coupled.
- `WRAP_LEGACY`: hydrology semantics have a fixture-only R6 boundary, but the B6 engine/runtime is **not** called. This is not a production adapter.
- `REFERENCE_ONLY`: all source artifacts listed above; the preflight records the bounded climate/hydrology register dependencies and matching hashes.
- `NOT_REUSABLE`: no source is declared scientifically invalid. None was directly reusable as a general R6 service without the new state/provenance boundary.

## New R6 core surface

`src/arcana_worldsim/r6/` adds deterministic typed IDs, support/authority-separated immutable domain-state envelopes, six distinct temporal record roles, provenance records and traversal, a replaceable append-only JSON history store, checkpoint/restart metadata with identity compatibility checks, metadata-first climate binding, fixture-only hydrology normalization, and support-aware state queries. Synthetic tests verify serialization, isolation, semantic validation, unknown propagation, provenance, and checkpoint equivalence. No scientific provider values are downloaded or replayed.

## Known limits

The file store is a Wave-1 reference backend, not the final database. It is append-only at the record API and atomically creates individual JSON files; multi-record transactions, concurrent-writer coordination, range-time query planning, spatial indexing, and database migration are not implemented. The hydrology boundary proves only typed input alignment and fixture normalization; it is not ready to execute the B6 generator. The climate boundary validates caller-supplied metadata/values and does not parse NetCDF/HDF5 files. Authority-register basis reconciliation remains an explicit prerequisite before scientific provider/domain state is consumed.
