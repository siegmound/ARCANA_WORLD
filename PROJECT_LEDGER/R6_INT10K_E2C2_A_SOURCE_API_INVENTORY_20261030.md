## Confirmed source contracts

- `src/arcana_worldsim/r6/regional_geological_evolution.py`: `advance_region` creates full annual snapshot `{'time_year': year,'cells':json.loads(_canonical(cells))}`, appends to transient `out['snapshots']`, emits `REGIONAL_YEAR_RECORD`, `REGIONAL_EVENT`, then `REGIONAL_SNAPSHOT` to `history_consumer`; `run_regional_segment(... history_independent_continuation=True)` builds history-free frontier for restart.
- Each newly deposited object is appended to destination `cell['deposits']` and includes eight fields: `material_id`, `mass_kg`, `density_kg_m3`, `source_cell_id`, `destination_cell_id`, `erosion_time_year`, `transport_time_year`, `deposition_time_year`, plus **`event_id`** (nine keys total). The emitted `DEPOSITION` event contains only `kind`, `material_id`, `mass_kg`, `source_cell_id`, `destination_cell_id`, `time_year`. Thus **cannot reconstruct deposit array exactly from existing DEPOSITION events alone**; per-cell position/order, event_id, density and full timestamps need retained supplemental data. Existence of append writes does not yet prove no mutation/deletion via other paths; require full scan + archive sample.
- `src/arcana_worldsim/r6/int10k_history_independent.py` `HistoryCollector.emit` accepts four kinds (`REGIONAL_YEAR_RECORD`, `REGIONAL_SNAPSHOT`, `REGIONAL_EVENT`, `UNIFIED_STEP`), JSON canonical-clones each and validates ordinal positions for regional annual records/snapshots and unified steps. `HistoryReader` reads exact annual snapshots/material lists and unified Deep inventory, refuses unarchived time/cell/volume; provenance retrieval scans annual event records.
- `src/arcana_worldsim/r6/store.py` `HistoryStore.append_transaction(records, expected_parent_view_id=...)` switches an immutable committed read view atomically, with journaling, stale-parent conflict, rollback/recovery; `read_view()` pins a read-consistent snapshot. `_transaction_record` **does not accept arbitrary `dict` deltas**: it accepts specifically `DomainStateEnvelope`, `ProvenanceRecord`, `EventRecord`, `CheckpointEnvelope`, `RefinementBranchEnvelope`, `ForcingRecord`, `ReplayRecipe`, `RefinementReconstructionRecipe`, `TemporalRecord`. Each typed record is re-parsed and ID-checked before publication; new adapter must map all delta semantics onto an existing approved typed record or introduce a separately reviewed typed schema/transaction change.
- `src/arcana_worldsim/r6/temporal.py` `TemporalRecord.create` and `EventRecord.create` derive content identities and carry history_id, branch_id, time_key, provenance_refs and details; EventRecord also has spatial/temporal support and causal state references. `DomainStateEnvelope` requires explicit time/spatial support, authority and support class; `UNKNOWN`, `NOT_APPLICABLE`, `OUTSIDE_SCOPE` must not carry fabricated values.
- `retention.py` `MinimalStateContract` restricts `SYSTEM_MEMORY` from DISCARD, requires reconstruction refs for DERIVE/REFINE, and validates materialized, forcing and static identities; `query.py` `HistoryQueryService.state_at()` returns `UNKNOWN`, `MISSING_TIMESTAMP`, `OUTSIDE_SUPPORT`, `CONFLICT` etc instead of inventing state. `replay.py`/`refinement.py` depend on stable checkpoints, parent state IDs and pinned store read views.
