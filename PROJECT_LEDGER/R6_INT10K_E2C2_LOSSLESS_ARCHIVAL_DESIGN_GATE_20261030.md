# ARCANA R6 INT10K E2-C2 — lossless historical delta + deterministic reconstruction design gate

**Status:** DESIGN / SOURCE-AUDIT NEXT. No source patch, FAIR run, archive rewrite, scientific promotion or new GitHub engine commit authorized by this document. Date 2026-10-30. Do not confuse E2-C1 (source checkpoint projection) with E2-C2 (history *storage* without quadratic duplicate snapshots).

## Mission (authoritative user requirement)

The simulation must preserve evidence of **geology, water, climate, Deep resources and their distribution, flora/fauna, resources/material movement, human settlement and future societies** at positions/times; queries must retrieve historical states exactly where supported, and targeted refinements must bind to the original causal state, input/provider provenance and UNKNOWN gaps. Current INT10K 3×3 synthetic benchmark is a test bed, not a scientifically populated ARCANA world. NEVER replace missing data with inferred facts or silently degrade history into population-only time series.

## Existing hard evidence and constraints

- Original immutable FAIR 1000Y noncanonical 3×3 archive: ~1,916,080,917 bytes HISTORY.jsonl, 61,001 index records, ~92.6% bytes REGIONAL_SNAPSHOT. By y1000 regional snapshots carry ~11,000 deposits (~99.73% of a late full-snapshot payload). O(T²) total duplicated historical deposits causes growth in CPU and storage. Preserve original as an exact SHA oracle.
- E2-C1-R3 source FAIR commit `2c71370eb9a959c78121ce1c88ec8e9e37187787` is FAIR-local, not pushed. E2-C1-R4 operator PASS 104 regressions, per-kind exact stream SHA oracle for 3Y 1+2 (184 records) and 10Y 5+5 (611 records), exact checkpoint and balances. Manifest independent rehash remains next read-only gate.
- R6 B0 already provides `src/arcana_worldsim/r6/store.py` `HistoryStore` with `append_transaction`, transaction rollback/recovery, immutable records and committed pinned `read_view`; `retention.py` `MinimalStateContract` and MATERIALIZE/DERIVE/REFINE; `replay.py` `ReplayRecipe` and `execute_replay`; `query.py` `HistoryQueryService`; `checkpoint.py` `CheckpointEnvelope`; `refinement.py` branch/reconstruction recipe support. Integrate through an adapter and versioned record model, never a competing store with weaker atomic visibility.
- Source code `regional_geological_evolution.py`: each `advance_region` clones state, then each year appends a full `REGIONAL_SNAPSHOT` with `json.loads(_canonical(cells))`. `DEPOSITION` history events carry material_id, mass, source/dest cell and time **but not full deposit fields** such as stable `event_id`, `density_kg_m3` and all erosion/transport dates. Therefore event-only replay cannot reconstruct the entire `cells[].deposits[]` losslessly without supplemental deposit delta. **Do not assert existing events alone are sufficient.**

## Proposed staged architecture (non-binding until audit)

**E2-C2-A: authority and exact-field inventory, READ ONLY.** Enumerate `REGIONAL_SNAPSHOT` and `REGIONAL_YEAR_RECORD` schemas, `REGIONAL_EVENT` variety, `UNIFIED_STEP`, cell inventory, deposit object keys, material catalog and T0 initial snapshot, including any in-place mutation/removal of old deposits. Rehash a bounded sample at years 0,1,2,100,500,750,1000 against indexed payload hashes. Audit consumer order, committed-store `TemporalRecord`/`EventRecord` interfaces, and per-time query/replay/refinement contracts. Produce explicit lossless field coverage matrix: material_id, provenance/event_id, masses, density, order, location, transport/deposition/erosion time, Deep inventory, water/soil/terrain fields, `UNKNOWN`/unimplemented data status.

**E2-C2-B: journal grammar (design/test-fixture only).** Represent year-0 full root state (immutable); annual `REGIONAL_YEAR_RECORD` and unique material/transport/hydrology events; deposit-ID keyed **append or replace/remove** deltas as needed (never assume append-only deposit mutation without proof), order position in cell, provenance and all fields. Include immutable pre/post state hashes, parent hash, time/region/cell ID, schema/provider provenance, no accidental float re-rounding, annual bundle manifest and transaction record IDs. Keep direct documented source status; never invent Deep forcing/coupling. A sparse checkpoint is a *restart state*, not a substitute for complete query history.

**E2-C2-C: B0 adapter into existing HistoryStore.** Store a per-year atomic transaction of record/events/material deltas/available exact query projection + checkpoint refs, committed view only. Retention contracts must distinguish materialized state, derivable-from-journal state, refinement-required gaps, static data, forcing and intentionally discarded intermediates. Reuse existing provenance/branch/replay recipe identities. Verify multi-process reader sees either full previous-year or full committed next-year state, never partial; fail closed if transaction interrupted, missing/duplicated fragment, changed SHA, unknown schema/authority.

**E2-C2-D: deterministic reconstruction/read APIs.** `reconstruct(year, spatial_support)` replays from authenticated nearest valid anchor plus ordered committed deltas; reproduce exactly the original canonical SHA256 `REGIONAL_SNAPSHOT` payload for each archived year and cell; retain `REGIONAL_YEAR_RECORD`, all event streams and exact Deep/unified conserved balances; query at a time where no data exists must be explicitly UNKNOWN or not archived, not interpolate. Support time-targeted and geography-targeted refinement whose dependencies all have stable hashes. Bounded random access must not secretly require scanning all past years when an anchor exists.

**E2-C2-E: exhaustive oracle and size/performance qualification.** Check years 0..1000 (1001 snapshots), 9 cells, all final 11k deposits including ordering/identity/mass/provenance, annual Deep/source input and all `REGIONAL_YEAR_RECORD` per-kind SHA, source/manifest integrity and zero made-up fields. Compare direct vs 1+2 and 5+5 restart and a 1000Y streamed reconstruction of the immutable **existing** archive (no numerical re-run unless independently authorized). Negative tests: missing/duplicate/reordered year or deposit, changed mass/float bit representation, corrupt hash, invalid schema, NaN, unavailable Deep provenance, power-loss during transaction, stale reader view, mixed parent/branch, missing anchor and incomplete coverage. Set acceptance criteria for bytes written, replay CPU, restart wall, peak RSS and query latency vs original 1.916GB fixture. No blanket speedup claim until measured.
